# Verilog CPU integration (WA824 RTL implementation in this package)

The real CPU must run the **machine bytes** emitted by the JS assembler, not the C source or Assembly text. The default runner is `backend/verilog/runner.py`, which invokes **Icarus Verilog** (`iverilog` and `vvp`) against the actual RTL in `backend/verilog/rtl/`. An optional `WA824_VERILOG_TRACE_CMD` environment variable can override the runner.

## Transport v1: per-program trace command

1. The Python development server runs `backend/verilog/runner.py` (or an override command) once per `/api/cpu/load`.
2. Runner stdin receives a **single JSON object**:

```json
{"origin":0,"bytes":[17,16,0,128,0,1]}
```

3. Runner loads these bytes into the simulated memory and clocks the **actual Verilog CPU**, recording one snapshot per step (plus an initial snapshot). The runner prints **one JSON object** to stdout:

```json
{
  "programSha256": "hex sha256 of the exact input byte array",
  "snapshots": [
    {
      "pc":0,"phase":"FETCH0","halted":false,
      "registers":[0,0,0,0,0,0,0,0],
      "instructionIndex":0,"instructionCount":2,
      "instruction":{"display":"..."},
      "alu":{"op":null,"a":null,"b":null,"result":null},
      "signals":{},"activeNodes":["pc","ifu"],"activeEdges":["pc-ifu"],
      "changedRegister":null
    }
  ]
}
```

`programSha256` must match `SHA256(bytes)` (exact bytes, not their JSON). Server rejects stale/unrelated traces. You must emit a *terminal snapshot with `halted:true`* once you decide the program ends. In the included runner, **one visualizer Step advances one RTL rising clock edge**: FETCH0, FETCH1, FETCH2, DECODE, EXECUTE, COMMIT. All six are actual states in `wa824_core.v`, not simulated phase names.

4. Server caches the snapshots and provides `/api/cpu/step` / `/api/cpu/reset` / `/api/cpu/snapshot` to the browser's `VerilogCpu` adapter. Any future WebSocket live-streaming implementation can replace this transport without changing the assembler.

## Connecting your Verilog project

- Included: `rtl/tb_wa824.v` and `rtl/wa824_ram.v`; machine words are 3 bytes, little endian. `Wx0` is hardwired to zero.
- Included: `runner.py`, which creates a temporary memory file, compiles all RTL with `iverilog`, runs it with `vvp`, and parses real RTL state lines into JSON. No ISA interpreter is used to generate PC/register state.
- Optional: set `WA824_VERILOG_TRACE_CMD` to use a *replacement* runner. The default works without this setting once `iverilog`/`vvp` are on PATH.
- The stock project contains the implementation. Unsupported ISA semantics (`SL/SLI`, `ECALL`, `MRET`) generate an RTL fault rather than guessing a behavior. `EBRAKE` halts as an explicitly documented demo policy.

## Important timing note

The included core truly transitions through `FETCH0/1/2 → DECODE → EXECUTE → COMMIT` at one clock edge per stage. RTL traces report the **completed** stage (with PC and register values sampled after the edge). `activeNodes/activeEdges` are optional *semantic annotations* generated by the runner, but must be arrays.

## v4 trace output extension

`runner.py` now accepts an optional string `input` in addition to `{bytes,origin}`. The Icarus testbench receives the UTF-8 stdin bytes via a temporary `.mem` file and emits `IO_PUT <decimal_byte>` and `IO_EXIT <decimal_word>` upon ECALL commits. The runner preserves each trace snapshot's architectural PC/register data from the actual Verilog simulation and adds `stdout` (cumulative text) and `exitCode` (`null` until exit). ECALL services 1, 2, 5 are now supported as a **new simulator ABI** (`docs/ABI-IO.md`); the earlier ECALL-unsupported statement above is retained as historical v3 documentation and should not be applied to v4.
